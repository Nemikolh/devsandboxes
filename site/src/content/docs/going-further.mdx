## Builds

`run`, `rebuild` and `start` keep building after you close the terminal. Ctrl-C cancels, and a cancelled `run` is undone. `-d` returns once the instance is registered, and `devsandbox logs --build web --follow` follows the build. A failing `postCreateCommand` keeps the container, so `logs` and `exec` can show why.

## Sessions

An `exec` from a terminal runs in a session that survives a closed terminal or a dropped connection. It ends with its program, the container or `--end`.

```bash
devsandbox exec web claude                    # gets -i -t on its own from a terminal
devsandbox exec web --sessions                # list them
devsandbox exec web --attach                  # back into a detached one
devsandbox exec web --end 1790000000-a1b2     # end one
```

## Who you are inside

You are the config's `remoteUser` (else `containerUser`, else the image's `USER`) with your host uid/gid, so workspace files stay yours. Mount into that user's home with `${containerEnv:HOME}`. [`identity = "image"`](/docs/config#environment) takes the image's users as written. A config that mounts into `/root` gets a prompt before `run` that offers to rewrite it.

## Links open on your desktop

`xdg-open`, `$BROWSER` and CLI logins in a sandbox open `http(s)` links in your host's browser. A `localhost` URL or an OAuth callback gets a port forward first, so `gh auth login` works. Scripts call `devsbd open <url>`.

[Profiles](/docs/config#profiles-profilesname) pick the browser:

```toml title="devsandboxes.toml"
[profiles.work]
[profiles.personal]

[sandbox.web]
folder = "../web"
image = "node:22"
profiles = ["work", "personal"]
```

```toml title="~/.local/share/devsandbox/profiles.toml"
[work]
open = ["google-chrome", "--profile-directory=Profile 2"]
```

```bash
devsandbox run web --profile personal
devsandbox profile web work             # switch, nothing restarts (P in the dashboard)
```

## GPUs

`hostRequirements.gpu = true` on a sandbox or a service gives its container every NVIDIA GPU. `run` stops before building when none is usable. `"optional"` runs without one. On a fleet, `run --place` sends it to a [machine](/docs/machines) that lends a GPU.

## The host daemon

Verbs, the dashboard, port forwards, notifications and links go through `devsandbox serve`, one per user on Linux and macOS. It starts on demand and exits after 10 minutes idle. Stopping it loses nothing. A sandbox with `autostart = "runtime"` needs it from login, which `devsandbox serve install` sets up as a systemd user unit or a LaunchAgent. Anyone who can open its socket can act as you, like with `docker.sock`. Editors talk to it with `devsandbox api --stdio` or the [Node API](/docs/node-api).
