This page picks up where the [quick start](/docs/quick-start) ends: a config root at `~/code/sandboxes` with a `web` sandbox. The dashboard takes over the terminal. Scripts and agents use these plain commands instead, and their output is uncoloured when piped.

## Start a sandbox

```bash
devsandbox run web           # prints the instance name: web
devsandbox exec -it web zsh  # a shell in the workspace
devsandbox exec web pnpm test
```

`run` builds the image (Features included), starts the `database` service, creates the container `devsandbox-web` with `../web` mounted as the workspace, runs `postCreateCommand`, and returns once it's up. The instance runs in the background.

`exec` runs in the workspace directory as the configured `remoteUser`, exits with the command's own status, and takes `-i` / `-t` only for interactive shells. Any command that takes a name accepts an instance name, a sandbox name or the repo folder's basename.

<Callout variant="note" title="When a lifecycle command fails">
  A failing `postCreateCommand` aborts `run` but keeps the container, so `devsandbox logs web` and `devsandbox exec web …` can show you why.
</Callout>

## A second instance

Run the same sandbox again:

```bash
devsandbox run web   # prints: web-2
devsandbox ps        # both instances
```

`web` is already using your checkout, so `web-2` gets its own **git worktree** in `~/code/sandboxes/.worktrees/web-2`, on a fresh `sandbox/web-2` branch. The two containers never share a working tree, which is the point when each one hosts a coding agent. Both reach the same global `database`.

Pick the name with `--name`, or check out an existing branch with `--branch`:

```bash
devsandbox run web --name fix-login --branch fix/login
```

## From any directory

Commands read the `config.toml` in the current directory. `-C <dir>` points any of them at another config root, so you don't have to `cd` first:

```bash
devsandbox -C ~/code/sandboxes run web
devsandbox -C ~/code/sandboxes
```

## Clean up

```bash
devsandbox stop web-2   # stopped, kept: `start web-2` resumes it
devsandbox rm web-2     # container, worktree and state entry gone
devsandbox gc           # reap services nothing references
```

`rm` also removes the instance's isolated services and network, and on a terminal asks before deleting the branch it created. Managed shell history is kept. Global services such as `database` outlive every `rm` until `gc` finds nothing referencing them.
