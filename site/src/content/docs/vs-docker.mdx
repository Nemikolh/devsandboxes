devsandbox puts devcontainers, compose-style services, git worktrees and [your other machines](/docs/machines) behind one CLI with docker's verbs, on docker, podman or Apple container.

<StacksDiagram />

| With docker                                   | With devsandbox                                                          |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| `devcontainer.json`                           | `[sandbox.*]` with the same image, Features and lifecycle commands      |
| `docker-compose.yml` services                 | `[services.*]`, one per instance or one shared by all                    |
| `docker compose up` a second time             | `devsandbox run web` again, with its own containers, worktree and branch |
| `-p 3000:3000`, decided up front              | `devsandbox port web 3000`, opened on demand                             |
| Keys mounted into the container               | Your ssh-agent relayed, keys stay on the host                            |
| Root-owned files in your checkout             | Your host uid/gid inside, on every runtime                               |
| No browser in the container                   | Links open in your desktop browser                                       |
| `--gpus all` on each command                  | `hostRequirements.gpu = true`                                            |
| `docker ps`                                   | `devsandbox ps`, or the dashboard                                        |
