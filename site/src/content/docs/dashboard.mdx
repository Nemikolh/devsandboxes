Run `devsandbox` with no arguments on a terminal to open the dashboard. The preview follows along as you scroll. Click it and press the keys each section suggests.

<DashboardTour>

<TourStep scene="instances">

## Instances

Each sandbox is listed with its instances under it. Repeat instances show their worktree (`⎇ .worktrees/web-2`). Detail shows the selected row. Tab `2` lists the service containers and who uses them.

<Try>`↑` `↓` to move, `1`–`4` to switch tabs.</Try>

</TourStep>

<TourStep scene="config">

## Config explorer

`enter` shows the config as written, next to the container's `docker inspect`. `t` flips to the resolved config.

<Try>`t` to toggle, `esc` to close.</Try>

</TourStep>

<TourStep scene="run">

## Run, stop, start

`r` on a sandbox row prefills `:run web`. The row shows the build step, `b` follows the build log, and `d` offers to cancel it. `s` stops or starts an instance and `l` shows its log. On an instance row, `r` renames it and `P` switches its [profile](/docs/going-further#links-open-on-your-desktop).

<Try>`enter` to run `web-4`, then `↓` to it and `b` for its build log.</Try>

</TourStep>

<TourStep scene="terminal">

## Terminal

`t` opens a shell in the instance, one tab per shell. `ctrl-]` or `F12` switches between it and the dashboard. Shells run in [sessions](/docs/going-further#sessions). An expanded instance lists them as rows, where `a` or `enter` attaches and `K` ends one. `a` on the instance picks a detached one.

<Try>type `ls` and `enter`, `esc` back to the dashboard, then `[` `]` to switch and `x` to close.</Try>

</TourStep>

<TourStep scene="ports">

## Port forwards

`p` prefills `:port web`. Forwards show in the Ports tab and outlive the dashboard until `d` stops one. Links a sandbox opens get forwards marked `(open)`.

<Try>`d` to stop it, then `1` `p`, type `8080:3000` and `enter`.</Try>

</TourStep>

<TourStep scene="vscode">

## VS Code

`o` or `devsandbox vscode web-2` opens VS Code attached to the instance, with the sandbox's extensions. It needs the Dev Containers extension and `code` on your `PATH`.

<Try>`↓` `o` to open it on `web-2`.</Try>

</TourStep>

<TourStep scene="inbox">

## Inbox

`devsbd notify "tests pass"` in a sandbox lands in the Inbox tab, marks the instance with `✉` and pops up on your desktop. Answer threads from a shell with `devsandbox inbox`.

<Try>`1` for Instances, where `web-3` lost its `✉`.</Try>

</TourStep>

<TourStep scene="prompt">

## Command prompt

`:` takes the CLI's verbs, like `run`, `exec`, `rm`, `profile` and `port`. Tab completes them and their names. `?` lists every key, and `q` quits.

<Try>`tab` to cycle, type `-3` and `enter` to remove `web-3`.</Try>

</TourStep>

</DashboardTour>

## Other machines <Experimental />

[Machines](/docs/machines)' instances show too, and every key but `o` works on them. The Machines tab (`5`) lists each machine, and `a` there turns its agent relay on or off.

## Keys

One-key actions fire bare or with shift only, so `ctrl-d` never removes an instance. `ctrl-c` quits, or copies over a selection. On a process row, `t` sends SIGTERM and `K` SIGKILL. The `?` screen has the rest.
