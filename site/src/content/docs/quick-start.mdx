## Prerequisites

- A running **docker**, **podman** or Apple **`container`** (default on macOS; `docker` elsewhere). Pick one with `DEVSANDBOX_RUNTIME=docker|podman|container`.
- **`git`** and **`curl`**. No devcontainer CLI.

## Install

The package is `devsandboxes`; the binary it installs is `devsandbox`.

## Write a config

A config root is a folder **outside** your repos holding one `devsandboxes.toml`; each sandbox points at a repo with `folder`, relative to it:

```text title="LAYOUT"
~/code/
├── sandboxes/
│   └── devsandboxes.toml
└── web/            # your repo
```

### By hand

Put this in `~/code/sandboxes/devsandboxes.toml`:

```toml title="devsandboxes.toml"
[services.database]
image = "postgres:16"
scope = "global"            # one container shared by all instances

[template.base]
caches = ["pnpm"]
persist-shell-history = true
[template.base.features]
"ghcr.io/devcontainers/features/node:1" = { version = "lts" }

[sandbox.web]
extends = "base"
folder = "../web"           # the repo, relative to this folder
services = ["database"]
image = "mcr.microsoft.com/devcontainers/base:ubuntu"
postCreateCommand = "pnpm install"
```

`[sandbox.web]` is a devcontainer definition in TOML; `extends` merges the `base` template into it ([how](/docs/config#templates-and-extends)), and `scope = "global"` gives every instance one shared postgres.

Check it from the config root. `ls` lists the sandboxes and fails loudly on unknown keys (with no config yet, `devsandbox run` on a terminal offers to write one):

```bash
cd ~/code/sandboxes
devsandbox ls
```

```text title="OUTPUT"
NAME  SOURCE                                             FOLDER  SERVICES  EXTENDS
web   image mcr.microsoft.com/devcontainers/base:ubuntu  ../web  database  base
```

## Run it

```bash
devsandbox run web                                  # prints the instance name: web
devsandbox exec web zsh                             # a shell in the workspace
devsandbox run web                                  # web-2: its own worktree, branch sandbox/web-2
devsandbox run web --name fix-login --branch fix/login
devsandbox ps
devsandbox stop web-2                               # `start web-2` resumes it
devsandbox rm web-2                                 # container, worktree, state entry
devsandbox gc                                       # services nothing uses
devsandbox -C ~/code/sandboxes ps                   # from any directory
```

Any command that takes a name accepts an instance name, a sandbox name or the repo folder's basename. `exec` runs as your user, in the workspace, with the command's exit status.

## The dashboard

Run `devsandbox` with no arguments: every instance and service live, the CLI's actions one key away (`r` run, `t` terminal, `?` every key). See the [dashboard tour](/docs/dashboard).
