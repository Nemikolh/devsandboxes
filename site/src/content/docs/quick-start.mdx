You need `git`, `curl` and a running docker, podman or Apple `container` (the default on macOS). `DEVSANDBOX_RUNTIME=docker|podman|container` picks one.

## Install

The package is `devsandboxes`. The binary it installs is `devsandbox`.

<InstallTabs />

## Give your agent the skills

Two [agent skills](https://agentskills.io) teach your agent the CLI (`devsandbox-cli`) and the config format (`config-toml-spec`). This installs them for the agents you pick:

```bash
npx skills add nemikolh/devsandboxes
```

Or copy the repo's `skills/` folder to wherever your agent reads skills from.

## Write a config

A config root is a folder outside your repos with one `devsandboxes.toml`. Each sandbox points at a repo with `folder`, relative to it.

<AgentPrompt prompt="quick-start" />

Or write it yourself, in `~/code/sandboxes/devsandboxes.toml`:

```toml title="devsandboxes.toml"
[services.database]
image = "postgres:16"
scope = "global"            # one container shared by all instances

[template.base]
caches = ["pnpm"]
persist-shell-history = true
[template.base.features]
"ghcr.io/devcontainers/features/node:1" = { version = "lts" }

[sandbox.web]
extends = "base"
folder = "../web"           # the repo, relative to this folder
services = ["database"]
image = "mcr.microsoft.com/devcontainers/base:ubuntu"
postCreateCommand = "pnpm install"
```

`devsandbox ls`, run from that folder, lists the sandboxes and fails on unknown keys. Every field is in the [configuration reference](/docs/config).

## Run it

```bash
devsandbox run web                     # prints the instance name: web
devsandbox exec web                    # a shell in the workspace
devsandbox run web                     # web-2, on its own worktree and branch
devsandbox run web --name fix-login --branch fix/login
devsandbox ps
devsandbox stop web-2                  # `start web-2` resumes it
devsandbox rm web-2                    # container, worktree, state entry
devsandbox -C ~/code/sandboxes ps      # from any directory
```

A name can be an instance, a sandbox or the repo folder's basename. Run `devsandbox` with no arguments for the [dashboard](/docs/dashboard).
