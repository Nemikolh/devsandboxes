## The problem

Open pull requests rot: the base branch moves on, conflicts appear, and nobody notices until review. The fix is mostly mechanical: merge, resolve, push.

A **dispatcher** sandbox runs a shell loop you own. For each PR that is conflicted or behind, it creates a **child** instance on the PR's branch, in its own worktree, merges the base in and starts <Agent /> only on a conflict. When it gives up, you get a notification.

The loop, in `pr-dispatcher/` next to `config.toml`, with a `.gitignore` for `babysit.log` and `.babysit/`. Set `REPO` and `chmod +x` it:

```sh title="pr-dispatcher/babysit-loop.sh" agent="claude" collapsed
#!/bin/sh
set -u
REPO=owner/web
STATE=.babysit            # per PR: "<run id> <head sha>"; gitignored
mkdir -p "$STATE"

# Runs inside the child, in the PR's worktree, with PR_NUMBER and BASE_BRANCH
# from `ensure --env`. Merging the base in (no rebase) keeps a plain
# `git push` enough; Claude Code only starts when the merge conflicts.
FIX='
set -u
fail() {
  git merge --abort 2>/dev/null
  devsbd notify --level error --key "pr-$PR_NUMBER" -- "PR $PR_NUMBER: $1"
  exit 1
}
git fetch origin "$BASE_BRANCH" || fail "git fetch failed"
if ! git merge --no-edit "origin/$BASE_BRANCH"; then
  claude -p "Merging origin/$BASE_BRANCH into this PR branch stopped on
conflicts. Resolve every conflict, keeping the intent of both sides, and run
the tests if the project has any. Then git add the resolved files and
git commit --no-edit. Do not push. If a conflict needs a human decision,
stop and leave the merge unfinished." \
    --permission-mode acceptEdits --allowedTools "Bash(git *),Bash(npm *)" ||
    fail "claude exited with an error"
  if [ -n "$(git diff --name-only --diff-filter=U)" ] ||
     git rev-parse -q --verify MERGE_HEAD >/dev/null; then
    fail "conflicts need a human"
  fi
fi
git push || fail "git push failed"
'

# Run a control command, retrying while no dashboard is open (exit 75).
ctl() {
  while :; do
    "$@" </dev/null; rc=$?
    [ "$rc" -eq 75 ] || return "$rc"
    sleep 60
  done
}

# One line per open same-repo PR: "<number> <head branch> <base branch> <head sha>".
OPEN='.[] | select(.isCrossRepository | not)
  | "\(.number) \(.headRefName) \(.baseRefName) \(.headRefOid)"'

# Cheap check, no agent: conflicted or behind its base.
needs_attention() {
  case $(gh pr view "$1" -R "$REPO" --json mergeStateStatus -q .mergeStateStatus </dev/null) in
    DIRTY|BEHIND) return 0 ;;
    *) return 1 ;;
  esac
}

while :; do
  # Same-repo PRs only ($OPEN): a fork's head branch isn't on origin. If gh
  # fails (logged out, offline), skip the round rather than retire every child.
  if ! gh pr list -R "$REPO" -q "$OPEN" \
       --json number,headRefName,baseRefName,headRefOid,isCrossRepository \
       >"$STATE/open.new"; then
    sleep 300
    continue
  fi
  mv "$STATE/open.new" "$STATE/open"

  while read -r num branch base head; do
    key="pr-$num"
    if [ -f "$STATE/$key" ]; then
      read -r id last <"$STATE/$key"
      case $(ctl devsbd run wait "$key" "$id" --timeout 0) in
        running) continue ;;                          # still on it
        "exited 0") ;;
        *) [ "$last" = "$head" ] && continue ;;       # failed on this head: wait for a push
      esac
    fi
    needs_attention "$num" || continue
    ctl devsbd ensure web --key "$key" --branch "$branch" \
        --env PR_NUMBER="$num" --env BASE_BRANCH="$base" >/dev/null || {
      devsbd notify --level error --key "$key" "PR $num: cannot start a child (exit $?)"
      continue
    }
    ctl devsbd run prune "$key" --keep 5 >/dev/null   # old runs' logs
    id=$(ctl devsbd exec "$key" --detach -- sh -c "$FIX") || continue
    echo "$id $head" >"$STATE/$key"
  done <"$STATE/open"

  # Retire children whose PR is no longer open.
  for f in "$STATE"/pr-*; do
    [ -e "$f" ] || continue
    key=${f##*/}
    grep -q "^${key#pr-} " "$STATE/open" && continue
    ctl devsbd rm "$key" && rm -f "$f"
  done

  sleep 300
done
```

It is the [sample from the automations guide](https://github.com/Nemikolh/devsandboxes/blob/main/docs/automations-guide.md#sample-pr-babysit-dispatcher), adapted: the child merges the base itself, a failure notifies you once per PR head, and fork PRs are skipped.

## Try it

```bash
devsandbox run pr-dispatcher                     # starts the loop (idle until gh works)
devsandbox exec -it pr-dispatcher gh auth login  # once, before the first child
devsandbox                                       # the dashboard: keep it open
```

Every five minutes the loop checks the PRs; a child `web-pr-<number>` appears in the Instances tab for each one that needs work. Failures land in the Inbox tab (`4`) and on your desktop. Follow along:

```bash
devsandbox exec pr-dispatcher tail -f babysit.log
devsandbox exec pr-dispatcher devsbd ls           # the children
devsandbox exec -it web-pr-123 bash               # look at a child
```

## How it works

- [`dispatcher`](/docs/config#devsandbox-extras) lets the dispatcher create, stop and remove children of the sandboxes in `spawn`; `devsbd ensure` / `exec` / `rm` are those requests.
- Control commands only succeed while the dashboard is open (exit `75` otherwise, which `ctl` retries); notifications wait for it.
- `autostart = "runtime"` restarts the dispatcher, and so the loop, after a reboot.
- Each child runs <Agent /> unattended with your `gh` login and pushes to your PR branches: keep `spawn` to what it needs and review what it pushes.

### Known limitations

- Same-repo PRs only: a fork's branch isn't on `origin`.
- Children outlive the dispatcher; remove orphans with `devsandbox rm web-pr-123`.
- `ensure` and `rm` run git on the host, which refuses a repo whose `.git/config` sets command-running keys (`core.sshCommand`, `credential.*`, …).
