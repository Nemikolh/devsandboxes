## The problem

An agent has to push its branch, but a private key copied into the container is handed to everything that runs there. devsandbox relays your host's ssh-agent instead, so the key never leaves the host.

<AgentPromptLink />

## Config

Nothing to enable. Add GitHub's host key and your git identity:

```toml title="devsandboxes.toml"
[sandbox.app]
folder = "../app"
image = "node:22"

[sandbox.app.postCreateCommand]
git-identity = "git config --global user.name 'Your Name' && git config --global user.email you@example.com"
known-hosts = "mkdir -p ~/.ssh && ssh-keyscan github.com >> ~/.ssh/known_hosts"
```

## Try it

```bash
ssh-add -l                                # on the host: your key is loaded
devsandbox run app --name fix-login
devsandbox exec fix-login ssh-add -l      # the same key, seen from inside
devsandbox exec fix-login git push
```

## How it works

- Every `devsandbox exec`, dashboard terminal and lifecycle command gets `SSH_AUTH_SOCK` relayed to your host's agent. A plain `docker exec` doesn't.
- The remote must be an ssh URL (`git@github.com:…`).
- On a [machine](/docs/machines), the agent is relayed only once you turn it on.
