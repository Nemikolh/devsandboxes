## The problem

An agent finishes its work on a branch and has to push it. Copying a private key into a throwaway container, or mounting `~/.ssh`, hands the key to everything that runs there.

devsandbox forwards your host's **ssh-agent** instead: ssh inside the sandbox asks it to sign, and the key never leaves the host. You only add GitHub's host key and your git identity.

## Config

<AgentPicker />

```toml title="devsandboxes.toml" agent="claude"
[sandbox.app]
folder = "../app"          # your repo, next to this config dir
image = "node:22"
# Your Claude Code login and settings, from the host.
mounts = ["source=${localEnv:HOME}/.claude,target=/root/.claude,type=bind"]
containerEnv = { CLAUDE_CONFIG_DIR = "/root/.claude" }

[sandbox.app.postCreateCommand]  # once, when an instance is created
git-identity = "git config --global user.name 'Your Name' && git config --global user.email you@example.com"
known-hosts = "mkdir -p ~/.ssh && ssh-keyscan github.com >> ~/.ssh/known_hosts"  # trust github.com
agent = "npm install -g @anthropic-ai/claude-code"
```

## Try it

```bash
ssh-add -l                                # on the host: your key is loaded
devsandbox run app --name fix-login
devsandbox exec fix-login ssh-add -l      # the same key, seen from inside
```

Start <Agent /> in it and have it commit and push its branch:

```bash agent="claude"
devsandbox exec -it fix-login claude
```

```bash agent="codex"
devsandbox exec -it fix-login codex
```

The remote must be an ssh URL (`git@github.com:…`); `https://` remotes never use the ssh-agent.

## How it works

- No config: every `devsandbox exec`, dashboard terminal and lifecycle command gets `SSH_AUTH_SOCK` relayed to your host's ssh-agent.
- A plain `docker exec` shell gets no forwarding.
- Works on Linux (docker, podman) and macOS (docker; Apple `container` untested). Native Windows: use WSL2.
