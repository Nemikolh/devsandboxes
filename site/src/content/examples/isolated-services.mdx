## The problem

Parallel agents on one database step on each other: one runs a destructive migration while another's tests expect the old schema, one flushes Redis in the middle of another's run. For throwaway work each instance should own its backing services and be free to wreck them.

That is the default. A service without `scope` is **isolated**: every instance that lists it gets its own container, on a network private to that instance, under the same hostname.

## Config

<AgentPicker />

```toml title="config.toml" agent="claude"
[services.postgres]
image = "postgres:16"                  # no scope: one per instance
env = { POSTGRES_PASSWORD = "postgres" }

[services.redis]
image = "redis:7"
command = ["redis-server", "--save", "", "--appendonly", "no"]  # in-memory only

[sandbox.api]
folder = "../api"                      # your repo, next to this config dir
image = "node:22"
services = ["postgres", "redis"]
# Your Claude Code login and settings, from the host.
mounts = ["source=${localEnv:HOME}/.claude,target=/root/.claude,type=bind"]

[sandbox.api.containerEnv]  # same hostnames in every instance, its own containers
DATABASE_URL = "postgres://postgres:postgres@postgres:5432/postgres"
REDIS_URL = "redis://redis:6379"
CLAUDE_CONFIG_DIR = "/root/.claude"

[sandbox.api.postCreateCommand]  # once, when an instance is created
agent = "npm install -g @anthropic-ai/claude-code"
```

## Try it

One instance per task, each with its own postgres and redis:

```bash
devsandbox run api --name fix-login
devsandbox run api --name add-search
devsandbox stats        # both instances and all four service containers
```

- `--name`: the instance name.

Start <Agent /> in each:

```bash agent="claude"
devsandbox exec -it fix-login claude
devsandbox exec -it add-search claude
```

```bash agent="codex"
devsandbox exec -it fix-login codex
devsandbox exec -it add-search codex
```

`devsandbox rm add-search` removes the instance with its services and network.

## How it works

- Services follow their instance through `stop`, `start` and `rm`.
- `devsandbox service rebuild redis` recreates every running instance's redis in place ([services reference](/docs/config#services-servicesname)).
- No host `ports` on isolated services (the second instance would collide): use `devsandbox port`.
