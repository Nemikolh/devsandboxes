Each host process that reaches a container runs its own `devsbd bridge` there. The bridge handshakes on each side,
then copies bytes until either end closes; only the shared `Mux` (`src/devsbd/mux.rs`), in the daemon and on the
host, parses frames. The same `Mux` carries the links between machines ([Fleet](/architecture/fleet)).

## Two handshakes

The bridge says `Hello` to the daemon first, then to the host, so a daemon of another protocol version fails the
bridge (exit `3`, `proto::MISMATCH_EXIT`) before the host sends a frame it can't parse. Only `VERSION` must match;
the build hash is informational. A mismatched container is retried every 5 minutes instead of every 10 s: only a
helper rewrite fixes it.

Each side sees only its own handshake, so caps are relayed by hand: the bridge tells the host `OWN_CAPS ∧ daemon
caps`, and passes the host's `Caps` to the daemon unchanged. `SSH_AGENT` is sent only with a live agent, `NOTIFY`
and `CONTROL` only by the host daemon's instance bridge (the one with a sink).

## Frames

One byte stream each way, little-endian, each frame written with a single `write_all` so writers can share it:

```text title="src/devsbd/proto.rs"
u32 stream_id | u8 kind | u32 len | payload[len]      (len ≤ 1 MiB)
```

| kind | name | stream | payload |
|---|---|---|---|
| 0 | `Hello` | 0 | `u32 version`, `u8` + build hash, `u32 caps` |
| 1 | `Open` | daemon id; host id for rpc | `u8 channel`: 1 ssh-agent, 2 http-proxy (reserved), 3 notify, 4 control, 5 rpc |
| 2 | `Data` | any | bytes |
| 3 | `Close` | any | optional reason (`connection refused`, …) |
| 4 / 5 | `Ping` / `Pong` | 0 | echoed |
| 6 | `Quit` | 0 | none: the daemon takeover |
| 7 | `Connect` | host id | `u16 port`, `u8` + host |
| 8 | `Window` | any | `u32 credit` (flow control on `Connect` and rpc streams) |
| 9 | `Eof` | any | none: half-close |
| 10 | `Caps` | 0 | `u32` host caps |
| 11 | `PortQuery` | 0 | `u32 id`, `u16 port`: who listens on that port in the container |
| 12 | `PortInfo` | 0 | `u32 id`, then per process `u32 pid`, `u8` + comm: the daemon's answer |

Channels 6–11 (`API`, `TRANSFER`, `PTY`, `TUNNEL`, `AGENT`, `ROUTE`) only run between machines
([Fleet](/architecture/fleet)). The header, `Hello`'s leading `version` and `Quit` are frozen, so any two builds can
report a mismatch and evict each other; unknown kinds are skipped, so frames are added without a `VERSION` bump.

**Stream ids.** The daemon allocates with the high bit clear (agent, notify, control), the host with it set
(`Connect`, `Open(rpc)`). Each side refuses the other's id space, a live id, or too many streams: 64 daemon-opened
and 256 host-opened (`Connect` and rpc together) per bridge.

## Routing in the daemon

The daemon keeps every attached bridge and routes each stream it opens to the newest one whose host serves it:

| stream | goes to | when there's none |
|---|---|---|
| ssh-agent | newest bridge with `SSH_AGENT` | held up to 1 s for one, then closed ("agent refused") |
| notify (notices, threads, URLs to open) | newest bridge with `NOTIFY` | stays in `/var/lib/devsandbox/outbox/`, retried every 30 s and on attach |
| control | newest bridge with `CONTROL` | answered `NoHost` (the CLI exits 75) |

A bridge whose `Caps` hasn't arrived counts as serving nothing (one whose `Hello` caps were 0, as ssh-agent only), so an agent-less `devsandbox port` that attaches
last can't take ssh away from the host daemon's bridge.

## Takeover

`start` on a running container rewrites the binary and starts a daemon of the new build. So does the serve daemon
before it respawns a bridge, which is how a daemon that took over after an upgrade (or a machine that followed the
authority's pinned build) reaches containers already running. The last start wins, upgrade or downgrade:

Same build hash → the second daemon exits 0. A pidfile with no hash yet (its owner still starting) counts as the
same build, so two concurrent starts never evict each other.
